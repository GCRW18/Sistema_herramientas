Cómo guardamos y mostramos archivos en Blob Storage

Fotos de herramientas y certificados de calibración ya no se guardan en la base de datos (antes iban como base64, inflando las tablas). Ahora el archivo vive en Blob Storage y en la BD solo queda una ruta corta. Todo el manejo de esa ruta pasa por un único servicio de Angular.

El recorrido de un archivo

1
Subir upload()

El usuario adjunta una foto o un PDF. El frontend lo manda por multipart al endpoint de subida. El backend guarda el archivo un instante en disco local, lo reenvía al servicio real de Blob Storage (fuera de este repo) y borra la copia local. La ruta corta es lo único que vuelve.

Endpoint: herramientas/SubirArchivosBs/uploadFileBlobStorage

Backend: ACTSubirArchivosBs → MODSubirArchivosBs

Respuesta: ruta_bs = containerName + '/' + name — ambos los devuelve el servicio externo de Blob Storage

2
Guardar la ruta

Esa ruta corta es lo único que se persiste en la base — nunca el contenido del archivo.

Qué esDónde se guarda
Foto de una herramienta he.ttool_files.path (purpose = 'location_photo')
Certificado PDF de calibración he.tmovement_items.certificate_file_url
3
Mostrarlo resolveImageSrc() / open()

Al pintar la pantalla, el servicio arma la URL pública a partir de esa ruta guardada.

// Descarga / vista de un archivo guardado GET {environment.filesUrl}sis_workflow/control/DescargarArchivoBlobStorage.php ?url_blob_storage=encodeURIComponent(rutaBs)

resolveImageSrc(v) se usa en <img [src]>, y open(rutaBs) abre PDFs en pestaña nueva.

Compatibilidad con lo viejo

!

Algunos registros antiguos todavía tienen el archivo como base64 en esa misma columna. isRutaBs(v) distingue una ruta nueva (corta, con / o extensión de archivo) de ese base64 heredado, así que no hace falta migrar los datos viejos — el mismo componente muestra ambos casos correctamente.
